How this dashboard works

A small internal portal that shows dealers — across the UK, Sweden and Norway — when bikes are likely to be available. It's fed by the weekly DUK plan workbook and the orders export. Each dealer logs in with a personal password and sees a country-wide availability grid plus their own committed orders.

The pages

  • Admin — at-a-glance counts (dealers, orders, plan rows, unmapped SKUs), the last-import details, and the notification panel for things that need attention.
  • Upload — drop in the latest plan workbook and orders export. Each upload replaces the plan and orders tables. Mapping table, dealers, embargoes and admin password persist.
  • Mapping — joins each order to its plan-model row using the leading token of the order's Material column (e.g. MSV4S → MTS V4 S / MTS V4 S MTO). The seed covers the 37 SKU prefixes seen so far; any new prefix that arrives on a future upload lands here as unmapped until you assign it.
  • Embargoes — hide selected models from every dealer's view. Tick rows in the table (↑/↓ to navigate, Space to toggle), then use Assign embargo date, Embargo all selected, or Unembargo all selected.
  • Dealers — manage per-dealer passwords. Each dealer is bound to a country (UK / SWE / NOR) and optionally to a dealer code, which is what makes their own committed orders show on their page. The admin password lives at the bottom of this page.
  • Dealer view — preview the grid every dealer sees. Same numbers regardless of which dealer; the only per-dealer difference is the "Your committed orders" panel.

How availability is computed

For each (model, month) cell:

available = DUK Sell In forecast
          − all open Demo / Courtesy orders (locked to their delivery month)
          − all open end-customer orders (FIFO'd by order creation date,
            cascading forward when a month fills up)

Stock / dealer orders are deliberately not subtracted — they're the elastic at the back of the queue and slide later when customer orders come in.

The traffic-light dots

  •   ≥ 10 available — comfortably open.
  •   1–9 available — limited; might fill up by the time a customer commits.
  •   0 or negative — fully booked (or overbooked) for that month.

Notifications

Two surface on the Admin home when relevant — both have inline actions:

  • Embargo may be over — a model is currently embargoed but has open orders against it. Click Lift embargo to make it visible to dealers again.
  • New bikes — plan models that appeared in the latest upload but weren't in the previous one. Click Embargo to hide them while they're being prepared, or Dismiss to mark reviewed.

Weekly routine

  1. Drop the two xlsx files into Admin → Upload.
  2. Open the Admin home and resolve any notifications.
  3. Check Mapping if the import flagged unmapped SKUs.
  4. Use Dealer view to spot-check the grid before dealers see it.

Source data shape

  • Plan workbook — the parser reads the Sell In block of the DUK_26 and DUK_27 sheets (column layout auto-detected). Other blocks (Sell Out, Dealer Inventory, Shipment) are ignored. Ross sometimes overrides DUK totals so the rollup is read directly rather than re-summed from the country sheets.
  • Orders export — filtered to Order Status Group = Open. The Material column's leading token is the join key. Country values UNITED KINGDOM, CHANNEL ISLANDS, IRELAND are all bucketed as UK; SWEDEN → SWE; NORWAY → NOR.

If something goes wrong

  • Dealer sees stale data — re-upload the latest xlsx via Admin → Upload.
  • New SKU appeared and isn't subtracted — it'll be flagged as unmapped on Mapping; assign it to a plan row.
  • Forgot the admin password — open the Supabase project's SQL editor and run UPDATE settings SET value='new-password' WHERE key='admin_password';
  • Want a clean reset — same SQL editor: TRUNCATE plan, orders; then re-upload. Dealers/embargoes/mapping stay intact.
